## ★ 阶段 1 落地：修截图脚本 + 闸门，并推翻「重跑即可修好」的假设

完整报告：**`docs/THUMBNAIL_ROOT_CAUSE.md`**（新建）。核心结论：脚本确有 7 处缺陷，
**但修完仍有 67/91 条重截失败 —— 根因在应用本身**。

### 截图脚本的 7 处缺陷（`scripts/screenshot-examples.mjs`，已修）
1. 就绪判据是固定 `waitForTimeout(1500)` → 重资产示例（Cesium 瓦片）1.5s 时 canvas 还没创建。
2. **成功判据是「字节数 > 500」** → 纯白 960×640 JPEG 就有 ~3.1KB，**509 条 `_thumb_map.json` 全绿、永不重试**。这是「整批空白却全绿」的直接原因。
3. **探针只截左上角 320×240** → 画在正中的内容被漏掉（kaikeba「4-一个点」全画幅方差 117、左上角 0）。
4. 用了同步 `getAllExamples()` → 懒加载 registry 下恒返回 `[]`，脚本静默空转。
5. 隐藏 chrome 的选择器 `.app-nav`/`.top-bar` 已过期，真实的是 `.demo-float-meta`（且 Teleport 到 body）。
6. 构图：截 `.demo-body` 而画布常只有 512×512 或 Cesium 默认 300×150 → 大片空白。
7. 缺 `--dry-run`/`--limit`；`--only-blank` 未隐含覆盖。

**构图修正只能用 `transform: scale()`**：改 canvas 的 `width`/`height` 会让「只绘制一次」的
demo 触发 resize 重分配缓冲区后**不再重绘 → 整幅全黑**（`graphics/animate_webgl/*` 全中招）。

**判据** = `全画幅方差 > 5` **或** `非主色像素占比 ≥ 0.0001`（纯色图两项都是 0；两者取或
是因为方差漏「暗且稀疏」、非主色占比漏「同色系渐变」）。

### 闸门（`scripts/verify-thumbnails.mjs`，已修）
新增「同图字节哈希分组」检测，**两档输出**：`>5 条` 报疑似占位图（`--strict` 拦截）、
`2~5 条` 仅列出供人工复核。**`SHARED_LIMIT = 5` 经实测正确，不要下调** ——
重截后 2~5 条的组里大量是**合法**同图（`kaikeba/06-颜色与纹理/07-纹理` 与 `13-纹理模块化`
重截后两张都有效、nonModal=0.246，只是这两课画面本来就一样；threejs-official 的
WebGL/WebGPU 双后端对同理）。**也不要用「<4KB」当硬失败**（`03-绘制三角形/3-线` 4095 B 是合法封面）。

### 剩余 67 条的 4 类**应用级**根因（未修，证据在报告 §4）

  → **这 82 个示例在线上也渲染不出来**，不只是封面空白。这是本次最重要的发现。
- **B（6 条，`earth-lessons/*`）**：`public/external-examples/**/*.js` 被 Vite **原样服务**，

  → `Failed to resolve module specifier "three"`。示例的 `clear-color="0xb9d3ff"` 解释了

  跨实例失效 → 球体无贴图（黑）。

### 数字修正：是 **84 个**，不是 82 个

1. 84 个组件用的是**课程自研渲染器** API：`compileSync` / `useProgram` / `setMeshData` /

### 修复（84 个组件零改动）
关键洞察：**两组组件走不同导入路径** ——
课程组（84 个）**直连** `core/Renderer.js`；OGL 组（`lights/*`、`3d-model/*`）走 **barrel** `index.mjs`。
所以只在**这一处分叉**即可，两组各拿各的：

| 文件 | 改动 |
|---|---|
| `scripts/generate-gl-renderer-esm.mjs` | **新增**：剥 UMD 外壳 → ESM |
| `src/examples/jsm-compat/gl-renderer.esm.js` | **新增生成物**（83.8 KB，禁止手工编辑） |
| `core/OglRenderer.js`（两棵树各一份） | **新增**：原 OGL Renderer 另存，内容不变 |
| `core/Renderer.js`（两棵树各一份） | **改写为转发**到课程原版 |
| `ogl/index.mjs`（两棵树各一份） | 改 1 行：`Renderer` 改从 `OglRenderer.js` 出 |

**为什么 UMD 不能直接 import**：它靠 `root["GlRenderer"] = factory()` 挂 `window`，

### ★ typecheck 的「假错」：并发负载会造出 TS6053

跑全量 `vue-tsc --noEmit` 时出现：
```
error TS6053: File '.../threejs-official/webgl/loader/WebglLoader3dtilesExample.vue' not found.
```

**排错过程（值得复用）**：
1. 文件确实存在、11752 字节、git 无改动、node 直接读成功、无扩展属性 → 排除文件问题
2. 窄范围 `-p`（只 include 这一个文件）→ **0 错** → 排除文件本身
3. 怀疑 fd 耗尽 → `ulimit -n` = 1048575（极大）→ 排除
4. `--listFilesOnly` 快速复现 → 直接被 **SIGKILL(137)** → 说明已到环境资源上限
5. `git stash` 掉 src 改动跑对照 → 0 错，但耗时 5m53s（我的版本 17m43s）
6. **独占机器重跑我的版本 → 1m24s / exit=0 / 零报错** ✅

**结论**：TS6053 是**负载导致的假错**（`readFile` 在资源压力下失败，被 tsc 报成「文件不存在」）。
同一份代码：无并发 1m24s/0 错；同时跑 eslint 17m43s/假错。**耗时也会膨胀 10 倍以上。**
→ 本仓库 `npm run verify` 的 typecheck 环节**必须独占跑**。
