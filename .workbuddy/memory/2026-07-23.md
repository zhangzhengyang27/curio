## ⚠️ 中文文件名封面在 vite dev 下破图 —— 已修复(commit 7144359)
- **证据**：vite dev(5180) 冒烟——ASCII 路径返回 `200 image/jpeg`；中文路径（registry URL 是 `encodeURIComponent` 逐段编码串）请求后返回 `200 text/html`（index.html SPA 兜底）→ 破图。507 中 134 张路径含非 ASCII（目录或文件名中文），其余 373 张纯 ASCII 正常。
- **根因**：vite 静态中间件在 macOS 上对 Unicode 文件名(NFC/NFD 规范化)解析失败，解码后的中文路径在磁盘上找不到 → 走 SPA 兜底。production 静态服务器解码正常，故仅 dev 受影响。
- **先试过「磁盘改编码名」——无效且已撤销**：曾把 134 张中文路径文件按 encodeURIComponent 重命名，但 vite 会先把 URL 的 `%XX` 解码成中文再查磁盘，编码名反而更对不上；且实测 vite 根本无法服务中文名文件（建的测试文件原始/编码 URL 都兜底）。故放弃重命名，还原到提交的 Phase 2 中文名状态。
- **实际修复**：在 `vite.config.js` 新增 `serveUnicodePublic` 插件(dev only, apply:'serve')，在 vite 默认静态中间件之前用 Node `fs` 按**解码后中文路径**直接读 public/ 下文件返回（Node 能解析 macOS Unicode 名，vite 不能）；用 `server.middlewares.stack.unshift(pop())` 顶到中间件栈最前。已实测：中文文件、中文目录+中文文件、ASCII、首页均正常返回；仅 7 个真缺失(webgpu_particles_soft + 6 graphics 性能)仍 @error 兜底。已单独提交，未动 507 个磁盘文件与 registry。
