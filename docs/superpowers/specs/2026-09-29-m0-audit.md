## 增补建议(不构成与 spec 的冲突,记入 ledger)

1. **表单控件样式基线进 M1**:全局 `accent-color: var(--cu-primary)` + 自定义 checkbox/radio/range 样式,放 `theme.css`(豁免文件)。原生控件是两主题共有的最大 demo 指纹,成本极小。
2. **暗色图表标签**列入 M3 注意项:workbench ECharts label 在暗色下需描边/背景避让。

## 亮色模式质量结论(spec 决策点 1 输入)

**结论:只保对比度闸门,无需与暗色同级精修。**
证据:亮色顶栏/卡片/画廊整体协调、文字对比度足;主要缺陷(native checkbox、占位封面、chip 墙、双搜索)两主题共有,会随组件语法换装自然受益;唯一亮色独有问题为零(图表标签重叠是暗色特有)。亮色跟随 M1 数据色板与新组件的亮色分支走即可。

## 与 spec 优先级的冲突

**无冲突。** 两条增补建议(表单控件基线进 M1、图表标签列入 M3)不改变 spec 的里程碑结构,由执行者记 ledger ruling 后吸收进 M1。
